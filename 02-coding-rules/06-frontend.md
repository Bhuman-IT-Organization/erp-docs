# Frontend (erp-web)

- **Applies to:** erp-web
- **Status:** complete (written from app/login, src/features/auth, src/features/branding and src/lib/api as built, 2026-09-21)
- **Enforced by:** see each rule; the architecture ESLint block in `configs/eslint/frontend.mjs`, `configs/eslint/base.mjs` for the unused-directive option, `src/__tests__/feature-shape.test.ts`, corepack yarn check:arch, corepack yarn check:brand

Twenty-seven rules, from routes to screen states. Every rule names what enforces it today; where the machinery is not built, the rule states the contract, the trigger that builds it ("built by the first screen that needs …"), and the check that enforces its absence until then. Explanations live in `03-architecture/04-frontend-components.md`.

## Rule format

Every rule in this file follows the same shape:

- **Rule:** one imperative sentence.
- **Where:** the folder or file it applies to.
- **Enforced by:** lint rule, CI check, or review checklist item.
- **Instead:** the pattern to use.

`Enforced by` names at least one of: an ESLint rule id from the architecture block (cited as `<constant>` plus the scope numbers `S1`…`S22` of "Layers"), a Vitest path, a `corepack yarn` script, `tsc` / `next build`, or the trigger phrase "built by the first screen that needs …" plus the check that enforces the absence today. "Review" appears only in addition.

## Layers

The architecture block, `configs/eslint/frontend.mjs` (byte copy in erp-web `configs/`, spread by erp-web's `eslint.config.mjs`), is a set of disjoint flat-config scopes, each carrying ONE `no-restricted-imports` and ONE `no-restricted-syntax` (flat config replaces a rule's options per file, so a file in two scopes would silently lose one): **S1** `app/**`; **S2** one scope per feature (`src/features/<f>/**` minus tests, stories and the legacy handoff; `FEATURES` is read from disk, so a new feature is scoped without editing the block); **S3** `src/features/auth/api/legacy-handoff.ts`; **S4** `src/lib/api/http.ts`; **S5** `src/lib/**` minus the eight `LIB_DOORS` (`http.ts`, `upload-file.ts`, `server-fetch.ts`, `config/env.ts`, `hooks/**`, `log.ts`, `i18n/format.ts`, `i18n/format.server.ts`) and tests; **S6** `src/lib/config/env.ts`; **S7** `src/lib/api/server-fetch.ts`; **S8** one scope per atomic layer (`src/components/<layer>/**` minus `atoms/Icon/**`); **S9** `src/components/atoms/Icon/**`; **S10** `lib/hooks/**`; **S11** `src/i18n/**` + `src/messages/**`; **S12** `TESTS` (`**/__tests__/**`, `**/*.test.{ts,tsx}`, `src/test/**`, `**/*.stories.tsx`, `types/**`: folded in because its only inhabitant is the upstream shim the root proxy test needs) + `.storybook/**`; **S21** `src/lib/log.ts`; **S22** the two format doors; **S23** `src/config/**/*.ts` minus the mirror and tests; **S24** `config/permissions.ts` (the mirror: the one scope WITHOUT `S_PERMISSION_LITERAL`); **S25** the ROOT SOURCES: Next 16's `proxy.ts`, `next.config.ts` and the root `*.d.ts`, all outside `app/**` and `src/**`; `proxy.ts` is named in the typed base object and in `ALL_SOURCE` as well, and the typed base matches `*.{ts,tsx}`, `types/**` and `__tests__/**` rather than one file name (naming `proxy.ts` alone is what left the other two root files on Next's base rules, with no typed rules at all). The build config and a declaration file want exactly these restrictions, so they join this scope instead of taking their own; **S26** `src/hocs/**/*.tsx`, the FE-16 second layer, which composes `@/components` and `@/lib` (so `G_COMPONENTS_FROM_LIB` is absent) but may reach no feature and fires `S_ALL` + `S_UI`; `check:arch` proves a feature import and a `fetch` fire on a HOC while a lib hook stays silent; **S27** `src/lib/api/upload-file.ts`, the tus door (M9): the one file without `P_TUS`, otherwise S5's restrictions plus `P_AXIOS`, `P_SWR` and `P_NUQS`. The count is `21 + FEATURES.length` (S1, S3 to S7, S9 to S12, S21 to S27, four layers, one per feature). Entries are constants: `P_AXIOS`, `P_AXIOS_TYPES`, `P_SWR`, `P_LUCIDE`, `P_TUS` (`no-restricted-imports` paths); `G_HTTP`, `G_CALL_API`, `G_FEATURE_INTERNALS(f)`, `G_FEATURE_COMPONENTS`, `G_ANY_FEATURE`, `G_COMPONENTS_FROM_LIB`, `G_UPWARD(layer)` (patterns); `S_FETCH`, `S_PROCESS_ENV`, `S_INTL`, `S_USE_EFFECT`, `S_SVG`, `S_HEX`, `S_PHYSICAL`, `S_PERMISSION_LITERAL` (`no-restricted-syntax` selectors; `S_UI` = svg + hex + physical, `S_ALL` = fetch + env + effect + intl + permission literal). After the scopes sit seven single-purpose objects that own rule ids no scope touches and may therefore overlap them: **S13** `MAGIC_NUMBERS`, **S14** `REACT` (`react-hooks/exhaustive-deps`), **S15** `I18N_LITERALS` (`react/jsx-no-literals`), **S16** `NO_CONSOLE`, **S17** `HYGIENE` (+ `react/no-danger`, described `eslint-disable`), **S18** `TEST_HYGIENE` (`vitest/*`), **S19** `A11Y` (`jsx-a11y` recommended). `linterOptions.reportUnusedDisableDirectives: 'error'` sits in its own object right after the global ignores (`base()` in `configs/eslint/base.mjs`). `corepack yarn check:arch` (`scripts/check-architecture-lint.mjs`) writes one probe per scope, asserts every entry fires and every permitted construct stays silent (146 expectations), and proves the scopes disjoint over `app/`, `src/`, `.storybook/`, `types/`, the root `__tests__/` and every root `.ts`/`.tsx`, the last DISCOVERED rather than listed, so a new root file is covered without editing the script (`ui/**` is ignored outright); it asserts `20 + FEATURES.length` import/syntax scopes.

The per-place table — what each folder may import, what it never imports, and the constants and scope numbers that enforce it — is `03-architecture/04-frontend-components.md` §"Layers as lint scopes" (moved there to keep this file inside its size budget; the rules below cite the same constants and scopes).

`fetch` is banned everywhere but S3 (`legacy-handoff.ts`), S7 (`server-fetch.ts`) and S12; `process.env` is banned everywhere but S6 (`env.ts`) and S21 (`log.ts`); `useEffect` is banned everywhere but S10 (`lib/hooks`) and S12; `Intl` / `toLocale*String` everywhere but S22 and S12; `lucide-react` and `<svg>` everywhere but S9 and S12; `tus-js-client` everywhere but S27 (`upload-file.ts`) and S12; a clean permission name (`module.resource.action`) everywhere but S24 (`config/permissions.ts`) and S12.

## Rules

### FE-01 `app/` holds route files only; a route reads env or params, calls one feature function and renders one feature page

- **Rule:** Keep `app/` to Next route files (`layout`, `page`, `loading`, `error`, `global-error`, `not-found`, `template`, `default`, `route.ts`, `globals.css`); a `page.tsx` is at most 30 lines, reads its env or `params`/`searchParams`, calls one feature function and renders one feature page; it may import `next`, `next-intl`, `react`, `@/features/<m>` (the index), `@/features/<m>/pages/*`, `@/features/<m>/api/*` (a server helper such as `getBranding`), `@/lib/**`, `@/components/**`, `@/i18n/**` and `@/messages/**`, never a feature component, `callApi`, the axios instance or the SWR policy; `src/lib` and `src/components` never import a feature.
- **Where:** erp-web `app/**`, `src/lib/**`, `src/components/**`.
- **Enforced by:** `G_FEATURE_COMPONENTS`, `G_CALL_API`, `G_HTTP` (`no-restricted-imports` patterns, messages tagged FE-01/FE-08) in S1; `G_ANY_FEATURE` and `G_COMPONENTS_FROM_LIB` in S4, S5, S6, S7, S10, S21, S22 (`src/lib`), `G_ANY_FEATURE` in S8, S9 (`src/components`); `src/__tests__/feature-shape.test.ts` `app/` clause (route-file names only, `page.tsx` ≤ 30 lines, every import matches the allowed prefixes); `corepack yarn check:arch` proves the S1 probe fires on a feature component, `callApi`, `fetch`, `process.env` and `useEffect`, and stays silent on a page and a server helper.
- **Instead:** `app/login/page.tsx` is the form: `searchParams` → `safeNext` → `getBranding()` → `<LoginPage>`; the composition lives in `src/features/<m>/pages/<Name>Page.tsx`, data access in `src/features/<m>/api/`; `export const dynamic = 'force-dynamic'` where the answer is per request (every route is dynamic today anyway — `cookies()` runs in `src/i18n/request.ts`).
- **Why:** freshers fill a fixed tree; `03-architecture/04-frontend-components.md`.

### FE-02 `src/components/ui` is generated by `corepack yarn ui:add <name>` and never edited; `field` + `Controller` is the form primitive

- **Rule:** Add a shadcn primitive only with `corepack yarn ui:add <name>` (`scripts/ui-add.mjs`: `corepack yarn dlx shadcn@4.21.0 add <name>` from the `radix-nova` registry, then it rewrites `src/components/ui/.manifest.json` with each file's sha256); never edit a file under `src/components/ui/`; build forms on `field` (`Field`, `FieldLabel`, `FieldError`) with react-hook-form's `Controller` — the registry's `form` item is deprecated; `components.json` is `rtl: false` and the generated primitives carry a few physical classes (`text-left`, `ml-4` in `field.tsx`; `has-data-[icon=inline-start]:pl-2` on every `Button`) that `UI_PHYSICAL_RESIDUE` in `src/test/render.tsx` subtracts — regenerate the primitives with `rtl: true`, which empties that list, when the first screen renders `FieldDescription`, a multi-error list or an icon button under `ar`.
- **Where:** erp-web `src/components/ui/**`, `components.json`, `scripts/ui-add.mjs`.
- **Enforced by:** `src/__tests__/feature-shape.test.ts` manifest clause (the manifest's key set equals the `.tsx` files in `ui/` and every sha256 matches — one byte of hand editing fails with "regenerate with `corepack yarn ui:add <name>`, never edit"); `corepack yarn ui:add` is the only writer (`--manifest-only` re-seeds without adding); `eslint.config.mjs` `ignores` and `.prettierignore` keep the generated files unlinted and unformatted so they never drift by tooling; the `rtl: true` regeneration is built by the first screen that needs it — until then `src/test/render.tsx` (`UI_PHYSICAL_RESIDUE`) names the residue and `src/features/auth/components/__tests__/LoginForm.test.tsx` proves the form's own classes are logical.
- **Instead:** Customise by a wrapper in `src/components/atoms/<Name>/` or a `cva` variant in `<Name>.variants.ts` (FE-06); a primitive that cannot be composed is a design question, not an edit; the login form styles the primitives with class-string constants translated from the legacy view (`LABEL`, `INPUT`, `PRIMARY`, `SECONDARY` in `src/features/auth/components/LoginForm.tsx`) — the 1:1 rule at work, not a variant system.
- **Why:** customisation by composition, never by copying; erp-web `README.md` "Known deviations"; `03-architecture/04-frontend-components.md`.

### FE-03 `process.env` is read only in `src/lib/config/env.ts` (plus `NODE_ENV` in `src/lib/log.ts`); the browser calls relative paths, the server calls `API_BASE_URL`

- **Rule:** Read `process.env` in exactly one application file, `src/lib/config/env.ts` (`import 'server-only'`, zod-parsed `loadServerEnv()`), with one named exception — `src/lib/log.ts` reads `process.env.NODE_ENV` (inlined by Next at build) to gate `debug`/`info`; declare no `NEXT_PUBLIC_*` variable; in the browser call only relative `/api/v1/*` paths (and `/erp_sso/handoff`) so every request goes through the Nginx origin the page came from; on the server fetch through `API_BASE_URL` (the Nginx origin), never a hard-coded host and never the api container directly.
- **Where:** erp-web `app/**`, `src/**`.
- **Enforced by:** `S_PROCESS_ENV` (`no-restricted-syntax` on `process.env`, message tagged FE-03) in S1, S2, S3, S4, S5, S7, S8, S9, S10, S11, S12 and S22 — omitted only in S6 (`env.ts`) and S21 (`log.ts`); `next build` (a client component importing a `server-only` module fails the build; `env.ts` has no unit test for that reason); `src/lib/__tests__/log.test.ts` (the gate is read per call, flipped with `vi.stubEnv`); `corepack yarn check:arch` (the S5 probe fires on `process.env`; the `log.ts` `lintText` stays silent on `NODE_ENV`; the format doors fire).
- **Instead:** `const env = loadServerEnv()` in a route or a `*.server.ts` helper, then `serverFetchJson(env.API_BASE_URL, path, schema, SERVER_TIMINGS.<x>.fetchMs)` (FE-09); a value the browser needs arrives as a prop from the server; `http.ts` has no `baseURL` on purpose.
- **Why:** env in erp-infra only; `03-architecture/05-strangler-fig-migration.md` (every call exercises the Nginx routing, so SSR and browser see the same map).

### FE-04 Every request fires from a handler or a hook, never an effect; `useEffect` lives only in `lib/hooks` with a `// effect:` reason

- **Rule:** Fire every request from an event handler or a data hook (`useCommonApi`, `useCommonMutation`); write `useEffect` only in `lib/hooks/**`, each preceded within two lines by `// effect: subscribe|dom|analytics: <reason>`; use the table: fetching → `useCommonApi`/`useList`; syncing state to props → derive in render; resetting on an id change → a `key` on the component; after-submit logic → the submit handler; URL sync → read the URL (FE-15); debounce → `use-debounce.ts` in `lib/hooks` (built by the first screen that needs it); an external store → `useSyncExternalStore` (the banner over `api-status.ts` is the worked example); session bootstrap → `use-session.ts`; a read that must be a POST (the mail preview renders a draft) → `usePostRead` in `src/lib/api/use-post-read.ts`, keyed on the path and the body, never an effect in `lib/hooks` (FE-16, trigger); a page's record label for the breadcrumb → `use-breadcrumb-label.ts` in `lib/hooks`.
- **Where:** erp-web `app/**`, `src/**` (`lib/hooks/**` is the one permitted home).
- **Enforced by:** `S_USE_EFFECT` (`no-restricted-syntax` on `useEffect(` and `React.useEffect(`, message tagged FE-04) in every scope but S10 and S12; `src/__tests__/feature-shape.test.ts` `useEffect` clause (outside `lib/hooks/` it fails; inside, the `// effect:` comment is required — comments are stripped before the scan, so prose does not count); `react-hooks/set-state-in-effect` and `react-hooks/set-state-in-render` (`error` through `eslint-config-next`) and `react-hooks/exhaustive-deps` (`error`, S14); `corepack yarn check:arch` (the S2 probe fires on `useEffect`, the S10 probe does not).
- **Instead:** `LoginForm` fires `login()` from `onSubmit` and derives `submitting`/`retryable` in render; `ApiUnreachableBanner` subscribes with `useSyncExternalStore(subscribeApiStatus, getApiStatus, …)`; a Server Component fetches the first paint through a feature `api/` function (`app/status/page.tsx`); act once on arrival (a page whose only trigger is being opened) → `useRunOnce` in `src/lib/hooks/use-session.ts`, the one effect for it (the `/login` resume and the `/logout?from=legacy` sign-out).
- **Why:** SWR owns server state; no effect-driven fetching; `03-architecture/04-frontend-components.md` state ladder.

### FE-05 A test per kind in a `__tests__/` folder beside the code, a colocated story per component; DOM tests opt in per file

- **Rule:** Every test file lives in a `__tests__/` folder beside the code it tests (never colocated; stories stay beside the component): `api|hooks|schemas/<f>.ts` → `__tests__/<f>.test.ts` (`*.server.ts` exempt — server-only by transitivity), `components/<N>.tsx` → `components/__tests__/<N>.test.tsx` starting with `// @vitest-environment happy-dom` plus a colocated `components/<N>.stories.tsx`, pages need none, `app/error.tsx` and `app/global-error.tsx` have none (the Next `reset` contract; `next build` compiles them); DOM tests render through `src/test/render.tsx` (`renderWithProviders`, which registers `afterEach(cleanup)` itself) with a fake transport (`fakeAdapter` on `http.defaults.adapter`, or a component's `adapter` prop); the hook tests prove a 500 read is retried, a 400 is not, and a mutation never is; no Jest.
- **Where:** erp-web `src/**/__tests__/`, `src/test/`, `vitest.config.mts`.
- **Enforced by:** `src/__tests__/feature-shape.test.ts` placement clause (a colocated `*.test.ts` fails naming the move), test-per-kind and story-per-component clauses, the happy-dom directive clause (`.test.tsx` line 1); `vitest.config.mts` (`environment: 'node'`, `include: src/**/*.test.{ts,tsx}`); `src/lib/api/__tests__/use-common-api.test.tsx` and `src/lib/api/__tests__/use-common-mutation.test.tsx` (the retry proofs, real timers with `Math.random` pinned); `corepack yarn test` in `corepack yarn check`.
- **Instead:** Copy `src/features/auth/components/__tests__/LoginForm.test.tsx` (seams `adapter`, `writeLocale`, `handoff`) or the template's `05-templates/frontend-feature/src/features/example-item/components/__tests__/ExampleItemForm.test.tsx` (`http.defaults.adapter`, cleared in `afterEach`); isolate the SWR cache per render with `<SWRConfig value={{ provider: () => new Map() }}>`; fixtures are neutral (`a@b.co`, `Example Company`).
- **Why:** Vitest in both repos; `02-coding-rules/02-testing.md`; the `__tests__` placement is the lead rule of 2026-09-20 (`02-coding-rules/05-backend.md` BE-21 is the backend twin).

### FE-06 Atomic layers import downward only; a shared component is `<Name>/` with four files; customise by wrapper or variant

- **Rule:** A shared component lives in `src/components/{atoms,molecules,organisms,templates}/<Name>/` as `<Name>.tsx`, `index.ts`, `<Name>.stories.tsx` and `__tests__/<Name>.test.tsx`, optionally `<Name>.variants.ts` (`cva`); a layer imports only `ui/` and the layers below it (atoms → nothing above; templates → everything); no layer imports a feature, `callApi` or the instance; a primitive is customised by a wrapper or a variant, never by editing `ui/`; `ApiUnreachableBanner` is the first organism and the form to copy.
- **Where:** erp-web `src/components/**`.
- **Enforced by:** `G_UPWARD(layer)` (`no-restricted-imports` pattern `^@/components/(<layers above>)/`, message tagged FE-06) in S8 for atoms, molecules and organisms (templates has nothing above it); `G_ANY_FEATURE`, `G_CALL_API`, `G_HTTP` in S8–S9; `src/__tests__/feature-shape.test.ts` layer clause (`src/components` holds only the five layer names; every entry is a PascalCase folder with exactly the four required files and the optional `variants`/`registry.json`; `__tests__` holds tests only); FE-02 for `ui/`.
- **Instead:** `src/components/organisms/ApiUnreachableBanner/` — the component, `index.ts` re-exporting it, four stories that set the external store synchronously in a named decorator, a happy-dom test; `app/layout.tsx` imports `@/components/organisms/ApiUnreachableBanner`.
- **Why:** atomic design over shadcn; `03-architecture/04-frontend-components.md` layer graph.

### FE-07 A feature is `src/features/<m>/` with the allowed entries; `index.ts` is its public surface; another feature is reached only through `@/features/<name>`

- **Rule:** A feature holds exactly `README.md`, `index.ts`, `api/`, `components/`, `hooks/`, `pages/`, `schemas/`, `messages/` (each code folder may hold `__tests__/`); `index.ts` is required once another feature or a route imports `@/features/<m>` by name, exports the client-safe surface and never re-exports a `*.server.ts` module; another feature's internals are never imported (`@/features/<other>/api/…` is a lint error from inside a feature); features use `@/components/ui/*` and the `@/lib/**` hooks directly.
- **Where:** erp-web `src/features/**`.
- **Enforced by:** `G_FEATURE_INTERNALS(f)` (`no-restricted-imports` pattern `^@/features/(?!<self>/)[a-z0-9-]+/`, message tagged FE-07) in S2 — one scope per feature, generated from `readdirSync('src/features')`; `src/__tests__/feature-shape.test.ts` allowlist clause (`FEATURE_ALLOWED_TOP`), `index.ts` clause and the `__tests__`-holds-only-tests clause; `next build` fails when a client component reaches a `server-only` module through an index; `corepack yarn check:arch` (the S2 probe fires on `@/features/branding/api/…` and stays silent on `@/features/branding`).
- **Instead:** `src/features/branding/index.ts` exports `BrandLogo`, `fetchBranding`, `FALLBACK_BRANDING`, `brandingSchema`, `Branding`, `THEME_TOKENS`, `themeCss`, `isSafeThemeValue` — never `getBranding` (`branding.server.ts`), which `app/` imports by its own path; auth imports `BrandLogo` from `@/features/branding`.
- **Why:** `02-coding-rules/05-backend.md` BE-03 is the backend twin (facade or events); `03-architecture/04-frontend-components.md`.

### FE-08 Reads are `useCommonApi` over `swrFetcher`, writes are `useCommonMutation` over `callApi`; string keys, prefix invalidation, axios only in `http.ts`

- **Rule:** `callApi(path, { method, body, headers, schema, adapter, timeoutMs, expectNoContent })` in `src/lib/api/call-api.ts` never throws and never retries (`ApiResult<T>` = `{ ok: true, status, data }` | `{ ok: false, status, code, retryAfterS, issues? }`); `swrFetcher(schema)` throws `ApiError` so SWR's global policy retries; `useCommonApi(path | null, schema, params?, options?)` = `useSWR(apiKey(path, params), swrFetcher(schema))` (a `null` path skips the request), `useList` unwraps `{ data, meta: { nextCursor } }` through `listSchema`; `useCommonMutation(path, { method, schema, invalidate })` = `useSWRMutation` over `callApi` with `throwOnError: false`, `revalidate: false`, and `onSuccess` → `mutate(matchesPrefix(p))` per prefix — never retried, `issues` surfaced; `createResourceHooks(base, schema)` composes `useList`, `useOne`, `useCreate`, `useUpdate`, `useRemove` (ids `encodeURIComponent`ed, every write invalidates `[base]`); keys are strings from `apiKey` (sorted query, `undefined` omitted), `keyPrefix`/`matchesPrefix` match exact, `?` and `/` continuations; reads never call `callApi`, writes never go through `swrFetcher`; `axios` is imported by `http.ts` only — `call-api.ts` may import its TYPES (the adapter seam); `swr` is imported under `src/lib` only; `idempotencyKey` on `callApi` and optimistic updates are built by the first screen that needs them (the first money/stock/document POST; the first UX that needs it).
- **Where:** erp-web `src/lib/api/**`, every `src/features/<m>/hooks/*.ts` and `api/*.ts`. `src/lib/api/use-post-read.ts` (`usePostRead`) is the one POST read: a read that must be a POST, SWR over `callApi` keyed on `['post', path, JSON.stringify(body)]` under the global retry policy, with no effect and no cache write; a POST that changes something stays `useCommonMutation` (`src/lib/api/__tests__/use-post-read.test.tsx`). `barcode-detector` has one importer, `src/lib/hooks/use-barcode-scan.ts` (the native `BarcodeDetector` when it reads EAN-13 and Code 128, else the ponyfill), pinned by `src/lib/hooks/__tests__/use-barcode-scan.test.ts`.

### FE-18 A migrated screen is 1:1 with the legacy FLOW, never its layout; the feature README records the view, the flow parity table, the drops and the messages

- **Rule:** **1:1 means flow parity, not visual parity** (lead correction, 2026-09-25 — the earlier reading, "rebuild it class for class", is what produced the nine findings of the UI review of that date): **1:1 in the workflow** — the same entry points and navigation paths, the same number of steps to finish a task, the same information available at each step, the same actions available on each screen, and the same terminology, taken from the legacy `_l()` keys so vocabulary does not shift under people; **ours to design** — layout, grouping, density, control choice, affordances, responsive behaviour, empty and loading states (the legacy UI is not a target; in most screens it is the thing being replaced); **never carried over** — a defect, a missing affordance, an unsafe control, or a field the new architecture has superseded (the per-user text-direction select is the worked example: direction is a function of the locale now, FE-19/FE-20, so porting the field reproduced cruft we had already replaced). ### FE-23 Storybook 10.6 on `@storybook/nextjs-vite`: a story per component, the `locale` global sets `dir`, `storybook:build` compiles and `check:a11y` audits every story in `check:phase`; `addon-vitest` by trigger

- **Where:** erp-web `.storybook/`, every `*.stories.tsx`.
- **Enforced by:** `src/__tests__/feature-shape.test.ts` story clauses (a colocated story per feature component; `<Name>.stories.tsx` required in every layer folder); `corepack yarn storybook:build` then `corepack yarn check:a11y` in `corepack yarn check:phase` (lead 2026-10-05); `storybook-static/` ignored in `.gitignore`, `.prettierignore`, `.dockerignore` and `eslint.config.mjs` `ignores`; `src/features/auth/components/__tests__/LoginForm.test.tsx` and the other `__tests__/*.test.tsx` files hold behaviour.

### FE-24 No `console` outside `src/lib/log.ts`; no `debugger`, `alert`, `eval` or loose equality; every `eslint-disable` is described and used; no focused test

- **Rule:** Log through `log` in `src/lib/log.ts` (`{ debug, info, warn, error }` — `debug`/`info` are no-ops unless `process.env.NODE_ENV === 'development'`, evaluated per call; `warn`/`error` forward to `console` and are the seam for a future reporting sink); no `debugger`, `alert`, `eval`, implied eval or `new Function`; `===` always, `const` unless reassigned, a parameter is never reassigned (properties excepted); no `dangerouslySetInnerHTML`; every `eslint-disable` carries `-- <reason>` and an unused one is an error; no `.only` reaches `main`, a `.skip` is a warning, every test asserts, no two tests share a title.
- **Where:** erp-web `app/**/*.{ts,tsx}`, `src/**/*.{ts,tsx}` (`HYGIENE`, S17), tests and stories (`TEST_HYGIENE`, S18).
- **Enforced by:** `no-console` (S16, ignores `src/lib/log.ts` and tests); S17 `HYGIENE` (`no-debugger`, `no-alert`, `no-eval`, `no-implied-eval`, `no-new-func`, `eqeqeq` `always`, `no-var`, `prefer-const`, `no-param-reassign` `{ props: false }`, `react/no-danger`, `@eslint-community/eslint-comments/require-description` `{ ignore: [] }`); `linterOptions.reportUnusedDisableDirectives: 'error'` in its own object, `base()` in `configs/eslint/base.mjs` (a config setting, not a plugin rule); S18 `TEST_HYGIENE` (`vitest/no-focused-tests`, `no-disabled-tests`, `expect-expect`, `no-identical-title`); `src/lib/__tests__/log.test.ts`; `corepack yarn check:arch` (console, debugger, alert, `==`, `var`, an undescribed and an unused directive, `it.only` and `dangerouslySetInnerHTML` all fire; `log.ts`'s `console.error` is silent).
- **Instead:** `log.warn('auth.handoff.failed', { status })` — an event name and labels, never a token; four justified disables exist in erp-web today — `LoginForm.tsx`: two legacy colours and one legacy glyph, each naming `login_admin.php`; `BrandLogo.tsx`: `no-img-element` on the customer-uploaded logo.
- **Why:** `02-coding-rules/01-typescript-and-lint.md` (TS-01..05); `02-coding-rules/05-backend.md` BE-24 (the same objects in erp-api).

### FE-25 The full `jsx-a11y` recommended set applies, with `no-autofocus` off for 1:1 parity; every story passes axe in `check:a11y`

- **Rule:** Every `.tsx` under `app/`, `src/components/` and `src/features/` passes `jsx-a11y`'s recommended rules (labels on controls, `alt` on images, keyboard handlers beside click handlers, no interactive `<div>`) with ONE deliberate departure: `jsx-a11y/no-autofocus` is off because the login form keeps the legacy `autofocus` for 1:1 parity (lead decision 2026-09-20); every form control is labelled through `Field`/`FieldLabel`; every story passes the axe panel of `@storybook/addon-a11y` (`parameters.a11y.test = 'error'` in `.storybook/preview.tsx` fails the story in the Storybook UI); `corepack yarn check:a11y` runs axe on every story in `check:phase` (FE-23; lead 2026-10-05), and a story that renders nothing by design declares `parameters: { a11yRunner: { rendersNothing: true } }`, the one way to declare an empty story (its root is asserted empty; there is no allowlist); text on a coloured background uses tokens that meet AA (`bg-destructive text-background`, not shadcn's `bg-destructive/10 text-destructive`, which is 3.98:1 at 14 px).
- **Where:** erp-web `app/**/*.tsx`, `src/components/**/*.tsx`, `src/features/**/*.tsx` (not `ui/**`, not tests), `.storybook/preview.tsx`.
- **Enforced by:** S19 `A11Y` in `configs/eslint/frontend.mjs` (`...jsxA11y.flatConfigs.recommended.rules` spread without re-registering the plugin `eslint-config-next` already provides; `'jsx-a11y/no-autofocus': 'off'`); `corepack yarn check:arch` (the S2 probe fires `jsx-a11y/*` on `<img src>`, `<div onClick>`, `<label>text</label>` and asserts `no-autofocus` ABSENT on `<input autoFocus />`); `.storybook/preview.tsx` (`a11y: { test: 'error' }`) for the panel; `src/components/organisms/ApiUnreachableBanner/__tests__/ApiUnreachableBanner.test.tsx` (`role="status"`); `corepack yarn check:a11y` (`scripts/check-a11y.mjs`, in `corepack yarn check:phase` after `storybook:build` (lead 2026-10-05): every story of `storybook-static` in headless Chrome at its declared size, `mobile375`, `desktop<W>` or `desktop<W>x<H>`, else 1280 and 375; it fails on any axe violation, play error, `console.error`, uncaught exception, unfinished render, empty root (no element and no text) or horizontal overflow, and `--prove` must fail with `image-alt`); `parameters.a11yRunner.rendersNothing` (`ApiUnreachableBanner` `Reachable`), whose root the runner asserts empty.
- **Instead:** `<Field data-invalid={invalid}><FieldLabel htmlFor={id}>…</FieldLabel><Input id={id} aria-invalid={invalid} /></Field>`; `role="alert"` on a server-error line, `role="status"` on a passive banner; open the story and the Accessibility panel before a PR.
- **Why:** the banner's contrast finding (`text-destructive-foreground` is not a shadcn 4 token); `03-architecture/04-frontend-components.md`.

### FE-26 Dates, times, numbers and currency are rendered only through the two format doors with `FORMAT_DEFAULTS`; never `Intl` or `toLocale*String` inline

- **Rule:** Format on the client through `useFormat()` (`src/lib/i18n/format.ts`, over next-intl's `useFormatter`) and on the server through `getFormat()` (`src/lib/i18n/format.server.ts`, over `getFormatter`), both applying `FORMAT_DEFAULTS` — `numberingSystem: 'latn'` (Latin digits under every locale, `ar` included), `calendar: 'gregory'`, `timeZone: DEPLOYMENT_TIME_ZONE` (`Asia/Dubai`; an assumption — it moves to branding or settings when the api serves it or a second customer exists); `Format = { date, dateTime, number, money, relativeTime, list }` — `date`, `dateTime`, `number(value, decimals?)` and `money` take the value only (no `Intl` options) and render in the customer's Perfex formats from `GET /api/v1/branding` `formats` (`FormatSettingsProvider`; `DEFAULT_FORMAT_SETTINGS` when none), `relativeTime` and `list` pass through from next-intl; no `Intl.*`, `new Intl.*` or `toLocale(Date|Time)?String` anywhere else.
- **Where:** erp-web `src/lib/i18n/format.ts`, `src/lib/i18n/format.server.ts` (S22), everything else.
- **Enforced by:** `S_INTL` (`no-restricted-syntax` selectors on `toLocale*String`, `Intl.` and `new Intl.`, message tagged FE-26) — a constant spread into every scope's syntax list (S1–S11, S21) and omitted only in S22, the two door files, and S12 (tests and stories); `src/lib/i18n/__tests__/format.test.ts` (the Perfex defaults; every date format, 24 h and 12 h, the separators, money placement and `remove_decimals_on_zero`; the customer's zone with `Asia/Dubai` as the fallback; Western digits under `ar`; `list(['a','b'])`); `corepack yarn check:arch` (the real S3/S4/S7 sources plus `void new Intl.NumberFormat()` fire FE-26; the two doors are silent on `Intl` and `toLocaleDateString`).
- **Instead:** `const f = useFormat(); f.date(row.createdAt)` and `f.number(count)` — the template's `ExampleItemList` renders `2026-01-03` for `2026-01-02T20:30Z` (the Perfex default `Y-m-d`, the day in `Asia/Dubai`), and the pager's range line keeps Latin digits under `ar`.
- **Why:** language is data; `03-architecture/04-frontend-components.md`.

### FE-27 A list component has loading, empty, error and loaded states; a form has pending, field-error and server-error states — each a test and a named story

- **Rule:** A `*List.tsx` component renders loading (`aria-busy` + `role="status"`), empty, error (`role="alert"` with a retry action for a retryable code, none otherwise) and loaded states; a `*Form.tsx` renders pending (controls disabled, the saving label), field-error (`FieldError` per field from `setError`) and server-error (one `role="alert"` line, Try again for a retryable code) states; each state is an `it` in the component's test and a named story export: `Loading`, `Empty`, `Error`, `Loaded` for a list, `Pending`, `FieldErrors`, `ServerError` for a form (extra exports free; an `ar`/`Rtl` story expected by FE-20); a copy of the template carries all seven (and `NoResults`, `Edit`, `SaveSummary`, `NotFound`, `Rtl`); `LoginForm` carries the three. A list's export is the kit's, never the screen's: the screen passes only `exportAction` (`ListExport`: `path`, `columns`, `labels`, and an optional `blanks` map for a column the screen shows as a word when empty), and `ListPageTemplate` renders one Export menu (`src/components/organisms/ExportMenu/ExportMenu.tsx`) with CSV, Excel, PDF and Print in the toolbar and, while rows are ticked, in the selection bar; ticked rows go to the api as `key`, otherwise every row the list's query matches; each item tells its cap before the click from `meta.exportLimit` (CSV, Excel) and `meta.printLimit` (PDF, Print); PDF is hidden when `direction()` of the locale is `rtl`; CSV, Excel and PDF download through `downloadFile` with the format, Print reads `format=print` rows through `readExportRows` (`src/lib/api/export-rows.ts`), mounts `PrintView` and opens the dialog through `usePrint` (`src/lib/hooks/use-print.ts`), whose print seam a story or test injects (FE-25); a retryable failure (network, timeout, 5xx) offers Retry, a refusal (over a cap, the PDF font, any other 4xx) says why and offers none. A plan that changes `erp-web/src/` or `erp-web/app/` carries the usability checklist of `04-design/02-ui-checklist.md` verbatim and ticks each item with evidence in its summary. The kit has two read paths, EditableTable's read cell and ListPageTemplate's own cell loop: a read rule (the empty value read as None, the long-text box) lives in one exported piece both use (`EmptyAsNone`, `readText`), never in one path or a screen. A grid (`editable.mode: 'grid'`) pins its trailing number columns at the inline end. A list or grid story proves with `expectFitsShell`'s `inFrame` that the columns the screen exists for lie whole in the frame at each shell width. A destructive bulk entry is `BulkAction.kind: 'destructive'` (red, after a separator), never a styled label.
- **Where:** erp-web `src/features/<m>/components/*List.tsx`, `*Form.tsx`, their `.stories.tsx` and `__tests__/*.test.tsx`; every plan that changes an erp-web `src/` or `app/` path.
- **Enforced by:** `src/__tests__/feature-shape.test.ts` story-export clause (classification by file-name suffix; `export const <State>` per required name); the template's `05-templates/frontend-feature/src/features/example-item/components/__tests__/ExampleItemList.test.tsx` (8 cases: the four states, export, the gate, `ar`) and `05-templates/frontend-feature/src/features/example-item/components/__tests__/ExampleItemForm.test.tsx` (14), one `it` per state; `src/features/auth/components/LoginForm.stories.tsx` (`Pending`, `FieldErrors`, `ServerError`); the export: `src/components/templates/ListPageTemplate/__tests__/ListPageTemplate.test.tsx` (the menu in both bars, `key` for ticked rows, the caps per item, no PDF under `ar`, Print, each refusal and Retry, nothing export-related while loading), `src/components/organisms/ExportMenu/__tests__/ExportMenu.test.tsx`, `src/components/organisms/PrintView/__tests__/PrintView.test.tsx`, `src/lib/api/__tests__/export-rows.test.ts`, `src/lib/hooks/__tests__/use-print.test.tsx`, and `src/lib/api/__tests__/download-file.test.ts`. The kit rules below: `src/components/templates/EditableTable/__tests__/EditableTable.test.tsx` and `src/components/templates/ListPageTemplate/__tests__/ListPageTemplate.test.tsx` (None for an empty cell on both read paths, the sticky actions, the destructive bulk entry after a separator), `src/test/in-shell.ts` (`expectFitsShell`).
- **Instead:** An error the member caused **inside a dialog** is rendered inside that dialog and leaves it open — the roles delete's 409 `errors.ERP-IDENTITY-0006`, shown through `ConfirmDialog`'s `featureErrors` with Delete disabled, is the worked example (a refusal the row already knows — a role its members hold — is shown from the moment the dialog opens, `refusedCode`), and a toast (or a dialog that closes with the row still there) is a member who cannot tell why nothing happened. Derive every state from the hook: `{ data, error, isLoading, mutate }` for a list, `{ trigger, isMutating, result }` for a form; `export const Error` in a stories file shadows the global in module scope and lint is silent — keep the name, the spec requires it.
- **Why:** a fresher fills a fixed set of states; a retryable failure offers a retry, a 4xx does not; `03-architecture/04-frontend-components.md`.
